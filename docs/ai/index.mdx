Restate is an open-source, durable runtime for agents and backends.  It provides the reliability infrastructure you need to run AI workloads in production, from simple LLM chains to complex multi-agent systems.
Restate runs the agent and everything around it, such as its sessions, sub-agents, and the workflows that it starts, on one durability layer, so you operate one system instead of several.

You can build agents on Restate in three ways:

<img src="/img/ai/restate-ai-build-options.png" alt="Three ways to build agents on the Restate runtime: a custom harness, agentlib, or an agent SDK integration" width={"80%"} />

| Approach | Use it when |
|---|---|
| [agentlib](#restate-agentlib) | A modern agent harness with best-in-class durability and a fast and responsive architecture, built natively on durable execution |
| [Agent SDK integrations](#agent-sdk-integrations) | Use Restate with popular SDKs like Vercel AI SDK, OpenAI Agents SDK, Google ADK, Pydantic AI, or LangChain |
| [Custom harness](#build-your-own-harness) | An off-the-shelf harness limits you, and you write your own agent loop in any language with a Restate SDK |

## Why Restate?

Agents in production run for minutes or hours, call tools with side effects, wait for people, and hand work to other agents. Whichever way you build, Restate gives you:

- **Recover work after failures, without paying a large durability overhead.** Restate adds only milliseconds per step, so every model call, guardrail check, step inside a tool, and parallel branch recovers on its own. After a crash or a deploy, only the steps that were running start again: you don't pay twice for completed model calls, finished tool work isn't redone, and the agent stays on the path it took.
- **No queue, workflow engine, or session database to run next to your agents.** Sessions, workflows, calls between agents, timers, and concurrency limits are all part of Restate, a single binary. You deploy and debug one system, without glue code that keeps several systems consistent when a request fails halfway. Each session handles one request at a time, so concurrent messages can't mix up the conversation.
- **Wait days for an approval without keeping the agent running.** Restate suspends an agent while it waits for a person, a webhook, or a timer, and resumes it when the answer arrives, also on serverless platforms such as AWS Lambda. You write no polling loops and no code to save the agent's progress.
- **See what a running agent does, and step in when it goes wrong.** The Restate UI shows each model call and tool call as it happens. You can [cancel, pause, resume, or restart](/services/invocation/managing-invocations) a running agent, and [concurrency limits](/services/flow-control) cap how many agents run at once, for example to control model spend.
- **Switch agent frameworks without rewriting your backend.** Sessions, workflows, and service calls don't depend on the harness, so you can move from an agent SDK to agentlib or your own harness and keep the rest of your application.

## Build your own harness

When an off-the-shelf harness limits you, build your own on Restate, so you don't have to rebuild fault tolerance yourself.
Start from the agent reference architecture: a complete TypeScript agent on Restate with human approvals, sandboxed tools, subagents, memory, and schedules.
Its skills teach your coding agent how to extend the agent and how to write the Restate code that it's built from.
